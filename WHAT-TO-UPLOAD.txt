NXONE - CUSTOMERS, AND EVERYTHING FROM THE LAST ROUND
====================================================

This replaces nxone-fixes.zip: it holds both rounds, so apply this one whether
or not you applied that. 957 tests, build clean, every change driven through
the screens in a browser. Site only; the API does not need redeploying.

  cd /workspaces/nxone
  unzip -q nxone-customers.zip
  cp -r nxone-customers/. .
  rm -rf nxone-customers nxone-customers.zip
  npm test && npm run build
  git add -A && git commit -m "Customers, payment terms, contracts, No GST, sign in, fixes" && git push
  npx wrangler deploy

CUSTOMERS ARE REMEMBERED ON THEIR OWN
  Saving or downloading any document saves its customer - no link to click.
  Matched by GSTIN first, then name, so billing them again never makes a twin.
  A detail changed on a later invoice is kept; one left empty is not treated as
  a request to forget it. Purchase orders are skipped: that is a supplier.
  Each document is now linked to its customer, so renaming a customer keeps
  their history together.

THE CUSTOMERS PAGE
  /customers, in the sidebar under Documents. Everyone you bill, who owes the
  most first, with what they owe, how much is overdue, and their past
  documents. Edit or remove any of them - removing a customer leaves their
  documents exactly as issued. "New invoice" opens one already addressed to
  them. People billed before this existed can be added in one click.

PAYMENT TERMS
  Set per customer: due on receipt, 7, 15, 30, 45, 60 or 90 days. Picking them
  on an invoice or proforma sets the due date. Not applied to quotations,
  whose second date is how long the price stands.

A BUG FOUND WHILE TESTING
  On several screens, something you added did not appear until the page was
  reloaded - a new contract, a new asset, an imported customer. Lists were
  cached against the store, which never changes identity, instead of against
  the workspace, which is replaced on every save. Fixed in 15 screens.
